## 1. Multi-User Architecture & Philosophy

The host `rbkasus` operates with two distinct user accounts collaborating on `LobMatrix`:
* **`rbk` (Admin / Sudo Access)**:
  * Has root/sudo privileges (group `sudo`).
  * Responsible for executing one-time system package installations (`openjdk-21-jdk`, `maven`, build essentials) into standard system paths (`/usr/bin`, `/usr/lib/jvm`).
* **`akash` (Quant Researcher / No Sudo)**:
  * Standard non-sudo user account.
  * Co-owns the project repository and data files via the shared group **`gitshared`** (GID `1003`).
* **Shared Access Paradigm**:
  * **System Tools**: `java`, `javac`, and `mvn` are installed system-wide in `/usr/bin`, making them natively available to both `rbk` and `akash` with zero individual PATH configuration required.
  * **Shared Workspace & Python Venv**: The workspace `/home/akash/projects/lob-matrix` and its virtual environment (`.venv`) use group inheritance (`gitshared` with SGID `chmod g+s` and `umask 002`) so both users can train models, read/write Parquet files, and run code without permission locks.
* **100% Free & Zero Cloud**:
  * **No paid cloud servers** (AWS/GCP/Azure) — runs entirely locally on `rbkasus` (Intel i5-8250U, 24 GB RAM).
  * **No paid cloud databases** — local DuckDB (in-process Parquet analytics) + embedded H2 (Postgres-compatibility mode).
  * **No paid AI subscriptions** — local multi-threaded CPU LightGBM / XGBoost / ONNX.
  * **Low Footprint** — `< 400 MB` RAM allocated, leaving all resources free for background servers (Minecraft, Jellyfin).

## 3. Step-by-Step Setup Commands

### Step 1: System-Wide Java 21 JDK & Apache Maven Setup

Executed once by **`rbk`** (with sudo) so that `javac`, `java`, and `mvn` become instantly available system-wide:

```bash
# 1. Update package index and install JDK 21, Maven, Python build tools
sudo apt update
sudo apt install -y openjdk-21-jdk maven python3-venv python3-pip python3-dev build-essential

# 2. Verify Java 21 compiler and Maven system-wide
java -version
javac -version
mvn -version
```

---

### Step 2: Git Repository Hygiene & Multi-User Safe Directories

Ensure both `rbk` and `akash` can use Git without "dubious ownership" warnings:

```bash
# 1. Add workspace safe.directory globally for the current user
git config --global --add safe.directory '/home/akash/projects/Order Book Analyses'
git config --global --add safe.directory '/home/akash/projects/lob-matrix'

# 2. Enforce shared group ownership and SGID on the repository
sudo chown -R akash:gitshared /home/akash/projects/lob-matrix
sudo chmod -R g+rwX /home/akash/projects/lob-matrix
sudo chmod g+s /home/akash/projects/lob-matrix
```

Create the Python virtual environment with `gitshared` permissions so both users can run training and research scripts:

### Step 4: Shared Local Data Hierarchy & Embedded Database Engine

Create the local data hierarchy with group inheritance:

```bash
cd /home/akash/projects/lob-matrix

# 1. Create data directories
mkdir -p data/raw          # Daily 40-byte binary .raw WAL envelopes
mkdir -p data/parquet      # Daily partitioned ZSTD Parquet files
mkdir -p data/db           # Local embedded metadata database files
mkdir -p data/models       # Exported model.onnx artifacts and JSON metadata

# 2. Apply group permissions so both rbk and akash can read/write data
chmod -R g+rwX data
find data -type d -exec chmod g+s {} +
```

#### 🗄️ Database Architecture (100% Local & Free):
1. **For Parquet Analytics (Python / Research)**: **DuckDB**
   * Operates directly on disk Parquet files (`data/parquet/**/*.parquet`).
   * Vectorized SIMD execution on CPU.
   * Zero memory bloat, zero background daemon, ₹0.00 cost.
2. **For Metadata & Session Tracking (Java Spring Boot)**: **H2 in PostgreSQL-Compatibility Mode**
   * Connection URL: `jdbc:h2:file:./data/db/orderbook_meta;MODE=PostgreSQL;DATABASE_TO_LOWER=TRUE;AUTO_SERVER=TRUE`
   * Provides full ANSI SQL, ACID transactions, and Spring Data JPA support.
   * Embedded inside the JVM — starts and stops automatically with Java.
